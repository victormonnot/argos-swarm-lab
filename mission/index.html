EXECUTION HISTORY

What happened, and when?

    Latest 30 events. Completion reports precede a same-boundary failure; dispatch follows both.

    Know the methods

    Assignment objective & reference ↗
    Allocation algorithms
    Fixed · greedy · Hungarian

    Choose owners in a fixed cycle, match nearest pairs, or minimize the current matching’s total distance.

    Execution mechanism
    Finite-state machine (FSM)

    Travel and service are explicit states with completion conditions. An assignment is only a target.

    Decision architecture
    Centralized for all three

    One coordinator assigns targets using exact status and position reports. This comparison changes the rule, while keeping authority fixed.

    Timing / communication
    Discrete · ideal reports

    0.1 s intervals. Failures are reported immediately, with no packet loss, heartbeat or communication delay.

    Execution: one browser model of planar point motion. Both views observe it. There are no obstacles, collision avoidance, sensor images or flight dynamics in this task-allocation experiment.

    PREDICT · RUN · INSPECT

    Same work. Different assignments.

    01 / OWNERSHIP

    Keep every task with its owner.

    Rule: fixed round-robin

    A1 owns T1/T4, A2 owns T2/T5, and A3 owns T3/T6. If A2 stops, can another agent take its queue?

    02 / GREEDY

    Choose the nearest pair.

    Rule: adaptive nearest-pair greedy

    Inspect the first assignment matrix. Taking the cheapest pair can leave another agent with a much longer trip.

    03 / MATCHING

    Minimize this dispatch’s cost.

    Rule: Hungarian algorithm

    Compare selected pairs and their summed distance. An optimal current matching does not solve every future route or failure.

    Compare the six measured reference runs

    Same starts, tasks, travel speed, service duration and budget. Each run stops at its first outcome. A blocked run’s short duration is not a successful completion time.

    Time is simulated. Travel includes unsuccessful work. Reassignments count an already assigned task moving to a different owner.

    LINEAR ASSIGNMENT PROBLEM

    A matching is a decision,
    not a finished mission.

    The Hungarian algorithm minimizes the sum of current agent-to-task distances. The finite-state executor then has to travel and complete service.

    When a job is interrupted, completed work stays completed, but its unfinished service must restart. Reallocation requires a free executor.

    cij = ‖pi − qj‖
    minimize ∑ cij xij
    at most one task per idle agent
    at most one agent per pending task
    number of pairs = min(idle agents, pending tasks)
    pi, qj
    Agent position and task position, in metres.
    xij ∈ {0, 1}
    Whether that agent–task pair is selected.
    Current distance objective
    Service time is identical for all tasks. No future jobs or failure schedule enter the matrix.
    Global measurements
    Mission duration, total travel and completed fraction are evaluation results, not the optimized dispatch cost.

    Unavailable is a modeled event.

    A2 stops at 5.0 s and its active task returns to pending. The coordinator learns this immediately. No real failure detector is implemented.

    What counts as finished?

    All six tasks must complete 2 s of service. If no assignment or execution can proceed while work remains, the result is blocked. Otherwise the budget is 60 s.

    Primary assignment source: H. W. Kuhn (1955), The Hungarian method for the assignment problem ↗. This workshop uses a rectangular minimum-cost variant, recomputed for idle agents and pending tasks. It does not claim an optimal multi-stop mission schedule.
